对比市面产品的优势与劣势

基于代码级事实基线（非产品宣称）与 20+ 竞品的横向调研，识别可辩护的差异化、被高估的卖点，以及三处需要立即修复的效度硬伤。

2026-08-04 代码基线：components/ + services/aiService.ts 竞品覆盖：4 阵营 / 24 产品 学术引用：7 篇
  1. 真优势不是"AI 批改准"，是"闭环完整"。LinguaFlow 走通了 分级出题 → 语体约束批改 → 二稿对比 → 错题进 Leitner SRS → CEFR/考试分纵向趋势 的全链路。调研的 24 个竞品里，没有任何一个跑通全链路——Grammarly 停在"改对这一篇"，Write & Improve 有 CEFR 和趋势但无错题复习，MOJIIQ 有 SRS 但只做日语。
  2. 第二真优势是形态，不是功能。纯前端 + localStorage + 自带 API Key + 免费。整条赛道除个别 beta 产品外全是订阅制（$5–30/月）或社区互惠制。数据不出浏览器、无账号、无月费——这条比"五套量规"更难被复制，因为商业公司做不了。
  3. 致命劣势：考试评分在"盲评"。analyzeWriting() 的 prompt 里压根没有题目正文，只传了 register。而 IELTS 的 Task Response、TOEFL 的 Development 考的恰恰是"是否回应题目"。这不是精度问题，是该维度的分数在结构上无意义。
  4. "多语种量规打分"这个差异点被高估了。韩语有 MyTOPIK / TopikIQ / ibttopik，日语有 MOJIIQ（还自带 SM-2 复习和 12 周曲线），西语有 Talkparty（还自带 register 维度）。不是空白市场，只是没人做"一个应用内多语种统一"。
  5. 不要在英语线正面拼分数准确性。2026 年 1 月英国文化教育协会已推出官方 IELTS WriteUp：16 项子维度、单题单模、每题需 90% 样本与考官误差 ≤0.5 分才准上线、上线后 10% 人工复核。个人开发者无法在校准工程上竞争，应主打覆盖面与闭环。

01 事实基线：LinguaFlow 写作工具到底是什么

以下均为代码核实结论，非 README 宣称。

写作能力分布在 4 个导航入口、7 种交互形态：自由写作、二稿改写、句型填空、看词造句、情境一句、写作树任务、主题作文。批改统一收敛到 services/aiService.ts 的三个函数：analyzeWriting、analyzeWritingRevision、analyzeGuidedWriting。

批改输出结构

返回类型 WritingFeedback 包含六个字段：整段润色重写 correctedText、错误建议数组 suggestions[{original, suggestion, reason}]（红删除线／绿高亮渲染）、总评 generalComment、cefrEstimation、考试分 examScores、语体点评 registerNote。

双层评分量表

考试维度换算
IELTStaskResponse / coherenceCohesion / lexicalResource / grammaticalRange，各 0–9（可 .5）overall = 四项均值
TOEFLdevelopment / organization / languageUse，各 0–5scaled = (d+o+l)/15×30
JLPT文字・語彙 / 文法 / 構成・表現，各 0–100估算 N5–N1
TOPIKvocabGrammar / contentOrganization / expression，各 0–100估算 1–6 级
DELEgrammar / vocabulary / coherence / taskAdequacy，各 0–100映射 CEFR
值得肯定的严谨处：代码在 JLPT 分支明确写了「JLPT 官方为选择题考试（文字・語彙／文法／読解／聴解），此处将学生的日语写作能力映射到 N 级量表作为估算」。JLPT 确无写作科目（官方 FAQ），这个坑作者已经绕开了，没有伪造不存在的官方量规。

三个在竞品中罕见的设计

分级宽容评分

Prompt 硬性约束："Do NOT penalize the absence of grammar/vocabulary above that level — a {level} learner is not expected to use advanced structures."

Grammarly 对 A2 学习者和母语作家用同一套规则，这是通用工具的结构性缺陷。

语体（register）维度

五档 casual / neutral / polite / formal / business，题库每题带标注，等级默认映射 A1→casual、B1→polite、B2+→formal。AI 需判断"该正式却太口语"。

全场仅 Talkparty（西语 tú/usted）与 Kunkun（日语敬语）有类似维度。

二稿对比批改

analyzeWritingRevision 把首稿 + 上次建议 + 二稿一起送审，输出 fixedIssues / remainingIssues / improved。

Write & Improve 支持重交但不做 diff 归因；其余竞品无此概念。

复习闭环

自由写作的 suggestions 会调 addErrorCards() 沉淀为错题卡，按 (original + language) 去重，进 Leitner 盒子，间隔 [0, 1, 3, 7, 16, 35] 天，box 1–5。复习界面遮蔽正确答案 → 自评"还会错／记住了"。WritingScoreRecord 最多留 500 条，渲染成 SVG 折线趋势图。

02 竞争格局：四个阵营，各有各的缺口

LinguaFlow 同时面对四类替代方案，威胁性质完全不同。

阵营 A · 通用 AI 纠错
  • Grammarly $12/月年付（月付 $30）— 仅英语，无 CEFR，无复习
  • LanguageTool €59.89/年 — 30+ 语言，规则解释最清晰
  • QuillBot $8.33/月 — 改写 23 语，语法检查仅 6 语
  • DeepL Write $7.49/座/月 — 多风格改写，基本不解释原因
  • Wordtune — 只能用英语写作
  • ProWritingAid $120/年 / 终身 $399 — 25+ 分析报告，偏文风非习得

共同缺口：0 个有 CEFR 分级，0 个有错题复习闭环。

阵营 B · 语言学习平台
  • Write & Improve（剑桥）免费 — CEFR A1–C1、趋势图、200 万+ 用户，仅英语、无 SRS、无 App；+£4.50/月 得 IELTS band
  • Busuu — 14 语，社区人工互改，课程止步 B2（韩语仅 A2）
  • Duolingo — 确认无开放式作文批改
  • MOJIIQ $7.99/月 — 日语，JLPT 校准 + SM-2 复习 + 12 周曲线
  • MyTOPIK / TopikIQ / ibttopik — 韩语按 TOPIK 官方四项量规打分
  • Talkparty — 7 语，DELE/SIELE 量规 + register 维度

最强威胁：Write & Improve（免费+权威）与 MOJIIQ（闭环最像）。

阵营 C · 人工批改社区
  • LangCorrect 100+ 语，2026 涨至 $8/月 / $60/年，开发者公开承认长期倒贴，可持续性存疑
  • Journaly 115 语，核心免费，Premium £5/月
  • HelloTalk 4000 万+ 用户，行内纠错，质量随缘
  • italki — 雅思写作批改 $29.99–40/次

不可替代之处：真人语感与语用直觉，AI 至今补不上。但无等级、无量规、反馈随机、伙伴会消失。

阵营 D · 中文市场与官方引擎
  • 有道写作 — C 端最完整对手，覆盖四六级/雅思/托福/考研，但官方明示"暂不支持其他语言"
  • 批改网 — 学校端为主，5000+ 学校
  • IELTS WriteUp（英国文化教育协会，2026-01）— 16 项子维度、单题单模、误差 ≤0.5 分才上线、10% 人工复核
  • ETS e-rater — 与单个人工的一致性高于两名人工之间（Attali 等 2010）
  • 秘塔写作猫 / 火龙果 — 通用润色，不做量规打分

03 优势：六条经得起追问的

剔除了"AI 反馈质量好"这类不可辩护的说法——底层都是同一批大模型，反馈质量不构成护城河。

1. 唯一跑通完整教学环的产品

出题（CEFR 分级 + 语体标注）→ 批改（多维 + 母语解释）→ 二稿归因 → 错误自动进 SRS → 分数进趋势图。竞品要么只做中间一段，要么缺尾部复习。

教学法背书：CATESOL Newsletter Vol.58(3) 中 ESL 教师实测 Grammarly 后给出的建议正是"先独立写→只采纳认同的→手动重写→记入 Editing Log 复习"。LinguaFlow 把这套人工流程自动化了——目前没有第二个产品这么做。

2. 本地优先 + BYO-Key：商业公司做不了的形态

数据不出浏览器、无账号体系、无月费、可离线保存草稿数据。全赛道调研 24 个产品，除个别免费 beta 外全部是订阅制或社区互惠制。

这条护城河的本质是商业模式不兼容：Grammarly 不可能让你自带 Key，因为那等于放弃收入。对隐私敏感、或已有 API 额度的技术型学习者，这是决定性的。

3. 分级宽容评分：真正的教学法差异

不因 A2 学习者没用虚拟语气而扣分。通用工具用统一规则集，会给初学者制造"满屏红线"的挫败感。

剑桥 Write & Improve 官方撰文承认刻意不一次标全错误，正是为了保护动机。LinguaFlow 用 prompt 约束达到同样目的，方向与权威产品一致。

4. 母语（中文）解释 + 非英语目标语

Prompt 强制 "Explain all feedback… in {nativeLanguage}"。学日语时用中文读懂"为什么这个助词错了"，这个组合在市面上极稀缺。

有道写作官方明示"只专注英文作文批改，暂不支持其他语言"；Write & Improve 全英文界面与反馈。中文母语 × 日/韩目标语这一格，几乎无人占据。

5. 语体维度：被整个赛道忽略的能力

"写对"和"写得体"是两回事。日语敬语、韩语阶称、西语 tú/usted、商务英语——语体错误往往比语法错误代价更高，却几乎无工具检查。

仅 Talkparty 与 Kunkun 有类似设计，且均为单语种。LinguaFlow 把它做成了题库层的一等公民（每题带 register 标注），而非事后检测。

6. 相对 ChatGPT 直接问：工作流与持久化

裸问 ChatGPT 能拿到同等甚至更好的单次反馈，但：不知道你上周错过什么、不产出结构化错题、无趋势、要自己出题贴量规、且顺手就能让它代写。

这是最诚实的一条——差异化在产品层，不在模型层。不要声称"批改更准"，要声称"它记得你"。

04 劣势：按严重程度分三级

致命影响核心价值主张的效度

① 考试评分在盲评——题目正文没进 prompt

已核实的调用签名：

analyzeWriting(text, targetLanguage, nativeLanguage, cefrLevel, targetExam, register)
                                                              ↑ 题目正文完全缺席

// WritingView.tsx:180
result = await analyzeWriting(text, ..., activeTopicResolved?.register);
                                          只传了语体，没传题目

IELTS 四维中的 Task Response、TOEFL 三维中的 Development，考的核心就是"是否切题、是否完成任务"。AI 看不到题目，这两项分数在结构上不成立。CompositionEditor 同样没传 node.title。这不是精度误差，是维度失效。

② 分数不可复现，且失败会静默污染趋势

temperature: 0.7 硬编码，无 seed、无 response_format JSON schema 约束。同一篇作文两次提交可能得到不同分数。更糟的是 parseAIJSON 解析失败时静默回落为 generalComment: "Analysis failed." + cefrEstimation: A1，但 XP 照发、addWritingScore 照写——一次解析失败就会在进步曲线上砸出一个假的 A1 坑。

③ AI 量规打分本身的效度天花板

研究设置结果
Nature Sci Rep 2024GPT-4o 零样本评分QWK 仅 0.437，PRMSE −0.617（比全给平均分还差）；对亚太裔作文系统性偏低
Mizumoto & Eguchi 2023GPT-3 按 IELTS Task 2 量规评 12,100 篇精确一致 54.33%，±1 级邻接一致 89.15%
Aydın 等 2025, SystemGPT-4o + CEFR 六维细化量规QWK 0.72、Pearson 0.73——接近人-人下限
ASAP/Shermis 2014 基准人-人一致性QWK 0.61–0.85
npj Sci of LearningLLM 评 IELTS Task 2一致性 ICC 0.68–0.72（优于教师 0.37–0.44），但绝对准确度只中等，换更强模型无改善
关键结论：瓶颈不是模型能力，是校准工程。裸 prompt 打分不可靠，但"细化量规 + few-shot + 锚样本"可把 QWK 拉到 0.72。LinguaFlow 目前只有量规文字描述，没有锚定样本、没有 few-shot、没有校准——处在效度谱系的低端。学术研究报告 GPT 系统性偏低，而第三方实测报告裸模型倾向偏高（偏差 0.5–1.5 分），这个矛盾本身就证明了分数会随模型版本和提示词漂移。

结构性受架构原则约束，非 bug

数据脆弱且备份不完整

BACKUP_KEYS 遗漏了 linguaflow_errorbook 与 linguaflow_writing_history——用户最珍贵的错题积累和数月进步曲线导不出、换设备即永久丢失。清一次浏览器数据即归零。

冷启动门槛极高

用户必须自己去申请大模型 API Key 并配置。对面 Write & Improve 是免注册、打开即用、完全免费。这个门槛会在漏斗第一步筛掉绝大多数非技术用户。

写作实际只支持 3 种语言

WRITING_SUPPORTED_LANGUAGES = [日, 英, 韩]，其余 8 种在 Gate 页标注"待开发"。而"支持 8/11 种语言"是产品的主要对外叙事之一，写作模块撑不起这个说法。

无移动端

写作练习天然适配碎片时间，竞品几乎全有 App。纯 Web + localStorage 意味着换设备就是换账号。

题库容量小

每 CEFR 等级仅 3–5 题，写作树英语 8 主题、日韩各 3 主题。对面 Write & Improve 有数百题分三档 + Business 专项，MyTOPIK 200+ 题，TopikIQ 370+ 题。

没有人的成分

LangCorrect / Journaly / HelloTalk 提供真人语感与语用直觉，这是 AI 至今补不上的。LinguaFlow 是纯单机产品，无社区、无对比、无同侪压力——而"孤独"恰恰是它自己定义的用户痛点。

工程债可修复，但正在削弱体验

  • 闭环有缺口：只有自由写作沉淀错题。引导式写作、写作树任务、主题作文全都不进错题本；主题作文既不进错题本也不进趋势记录，完成固定发 50 XP，与批改质量完全脱钩。
  • 重试按钮 bug：WritingView.tsx:326 把 MouseEvent 当作 isRevision 参数传入（truthy），只要已有首稿反馈，点"重试"就会误走二稿对比分支。
  • 写作树 mode 硬编码：WritingTreeView.tsx:75 恒传 'scaffold'，导致 B1/B2 的空脚手架任务 prompt 变成「模板：「」」。
  • 正文不自动存草稿：WritingView 的输入只存 React state，刷新即丢。
  • 二稿不检语体：analyzeWritingRevision 签名里没有 register 参数。
  • 已实现但零调用：generateReferenceEssay（含 A1–C1 分级长度的范文与提纲生成）完整实现却全项目无人调用；buildCompositionSections 的体裁切换未接 UI。另有 classifyInspiration、polishText、getWritingCoachFeedback 三处死代码。

05 战略判断

一句话定位建议：不要说"AI 批改你的作文"——那是红海，且拼不过。要说"它记得你所有写错的地方，并在你快忘记时让你重写一遍"。

该做什么

立即修三处效度硬伤

① 把题目正文注入 prompt（一行参数的事，直接决定 Task Response 是否有意义）；② 批改调用改 temperature: 0.2 + JSON schema 约束；③ 解析失败时不发 XP、不写趋势记录，明确报错让用户重试。

把 BACKUP_KEYS 补全

加入 errorbook 与 writing_history。在"无后端"原则下，导出即是用户唯一的数据主权保障——现在这个保障是漏的。

补齐闭环缺口

让引导式写作、写作树任务、主题作文的错误全部进错题本。闭环完整性是最大卖点，不该只在一个入口成立。

把 generateReferenceEssay 接进作文编辑器

已经写好的分级范文生成能力零调用，太浪费。"写完对比范文"是学习者高频诉求，且竞品普遍不提供。

不该做什么

  • 不要在英语雅思线拼分数准确性。IELTS WriteUp 用"单题单模 + 误差 ≤0.5 分才上线 + 10% 人工复核"筑墙，个人开发者无法在校准工程上竞争。英语线的正确打法是母语解释 + 复习闭环。
  • 不要宣称"多语种考试打分是空白市场"。韩语 MyTOPIK / TopikIQ / ibttopik、日语 MOJIIQ、西语 Talkparty 都已存在。真实的稀缺点是"一个应用内、中文母语反馈、多语种统一量规 + SRS"——现有玩家全是单语种孤岛。
  • 不要放弃 JLPT 的诚实表述。代码里"映射估算"的措辞是对的，UI 上也应保持，别为了卖点写成"JLPT 官方评分标准"。
  • 暂不考虑做社区。人工互改赛道 LangCorrect 已经在倒贴运营，冷启动成本极高，与"纯前端无后端"原则直接冲突。
总评：LinguaFlow 写作工具的设计密度高于大多数商业产品——分级宽容评分、语体维度、二稿归因、错题 SRS，每一条都体现了真实的教学法思考，这在个人项目里罕见。但它目前处在"设计已到位、实现有漏洞"的状态：三处效度硬伤（盲评、不可复现、静默失败污染数据）正在侵蚀它最想主张的价值。这些恰恰是低成本可修的。修完之后，"闭环 + 本地优先 + 母语反馈 + 多语种"这个组合，在 2026 年的市场上确实没有第二家。
